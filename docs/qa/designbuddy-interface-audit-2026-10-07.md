# DesignBuddy 全界面审查与修复建议方案

- 审查日期：2026-10-07
- 审查范围：`apps/web/public/login.html`、`role.html`、`studio.html`、`studio-workbench.*`、`studio-templates.*`、`apps/daemon/src/designbuddy-store.ts`、`designbuddy-commercial-projects.ts`
- 本文性质：修复建议与实施顺序，不包含本轮产品代码改造

## 1. 审查口径与界面库存

本轮按“用户可到达界面 + 可见操作 + 数据链路 + 响应式 + 可访问性 + 失败状态”逐项检查，而不是只检查静态视觉稿。

已纳入的界面库存：

- 2 个入口界面：登录/注册、首次角色选择。
- 11 个工作台主视图：首页、项目、生成工作区、第二大脑、模板、设计系统、社区、评审、交付物、团队成员、审批。
- 4 套角色配置：设计师、产品经理、开发者、管理者。
- 10 个账户弹层：套餐、积分、加油站、邀约、成长计划、设置、记忆与进化、外观、帮助与反馈、检查更新。
- 5 个项目工作台：文档、草图、上传、浏览器、设计体系。
- 18 套模板、每套 13 个命名页面，共 234 个模板页面状态。
- 56 个设计师 Starter 项目：50 个商业项目 + 6 个旧 Starter。

检查证据：

- `studio-workbench.js` 与 `studio-templates.js` 均通过 `node --check`。
- `login.html`、`role.html`、`studio.html` 的内联脚本均通过语法检查。
- 现有 Starter 测试覆盖了 50 个项目、10 个行业体系、每个体系 5 个布局编号、56 个持久化项目和部分交互，但当前只对首个商业项目做了完整 JSDOM 点击验证，并未逐个覆盖 56 个项目。

## 2. 总体结论

当前版本已经具备完整的产品外壳、较好的视觉基础、真实的项目持久化和可运行的项目工作台，但还不适合只做“样式微调”。最优先的问题是：**入口真实性、核心链路可用性、角色数据隔离、静态演示功能、模板结构重复、可访问性与项目列表性能。**

### 2.1 P0：必须先修复

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| P0-01 | 预览启动依赖临时 Sandbox 地址，旧地址会立即失效；启动命令还需要手工配置当前 Origin | 用户无法稳定打开右侧预览 | 增加统一 `preview-studio` 启动脚本，动态读取 `E2B_SANDBOX_ID`，自动设置 `OD_ALLOWED_ORIGINS`/`OD_ALLOWED_DEV_ORIGINS`，等待 Web、Daemon、Starter 初始化全部健康后才暴露预览 |
| P0-02 | 登录/注册使用 `fakeAsync` 和 `db-auth=demo`；任意邮箱与六位密码均可“登录”，Google/GitHub 也只是本地假成功 | 入口具有误导性，用户身份、角色与数据无法真正隔离 | 默认接入现有 OpenDesign 身份；如果产品坚持本地单用户模式，则删除密码和第三方登录，明确改为“进入本地工作区”，不能保留伪登录 |
| P0-03 | Agnes 未配置时，首页最主要的“发送并生成”链路不可完成 | 核心价值路径中断 | 启动时做服务端配置预检；发送前阻断并给出可操作配置入口；配置成功后再允许选择对应模型 |
| P0-04 | 首页“添加”面板中的附件、本地代码、Figma、连接器、MCP，以及“工作目录”仍触发 `toastDemo` | 与“所有入口均可用”的目标冲突 | 将附件接到现有上传工作台；本地目录接系统目录选择；Figma/连接器/MCP 接真实安装或授权流程；未实现项暂时隐藏，不能展示假入口 |
| P0-05 | PM/开发者/管理员项目仍是静态蓝图；“全部”还会拼接所有真实项目，导致不同角色看到设计师的 56 个项目 | 角色差异化不完整，数据范围错误 | 所有角色项目写入数据库；先按当前角色过滤真实项目，再计算筛选数量；静态样例迁移为对应角色 Starter，点击必须打开真实项目而不是只回填提示词 |
| P0-06 | 模板分享生成 `#template=...`，但路由只认识固定视图 Hash，没有任何代码解析该模板 Hash | “分享”复制的是无法还原模板预览的链接 | 定义 `#/templates/:templateId/:page?` 路由；首屏解析并打开模板；无效 ID 显示可恢复错误；增加分享链接往返测试 |
| P0-07 | 项目标题/创建者、评审标题/作者、真实设计系统标题/摘要直接进入 `innerHTML`，没有统一转义 | 重命名项目或同步数据可形成持久化 XSS | 所有服务端字符串统一用 `textContent` 或 `esc()`；新增恶意标题、作者、摘要回归测试 |

### 2.2 P1：随后修复

1. 234 个模板页面目前由 9 个渲染器生成，大部分渲染器只使用 `page % 3`，因此同一模板的 13 页主要是标题和数字变化，并不是 13 个真正不同的信息架构。
2. 模板内按钮多数只增加高亮并显示“已触发”，没有购物车、筛选、表单、审批、预订、支付等领域状态机。
3. “使用模板”只把模板名称填入首页提示词，不能复制 13 页结构，也不创建模板实例。
4. 项目页一次可创建 56 个完整 `srcdoc iframe` 缩略图；即使使用 `loading=lazy`，HTML/CSS 解析、内存与滚动成本仍然过高。
5. 社区、交付物、成员、审批和多数账户数据仍是静态数组或 `localStorage`，部分失败会静默回退成演示数据。
6. 英文模式不完整：50 个项目固定中文；模板画布仍大量硬编码英文；工作台部分生成内容固定英文。
7. 多数控件没有统一 `:focus-visible`；部分输入框主动 `outline: none`；项目预览弹层没有焦点陷阱、焦点恢复和 Escape 关闭。
8. 商业项目在手机断点直接隐藏第二、第三个 KPI、商品或内容，而不是重排/横向滚动，移动端会丢失信息。
9. 12 张封面图被 50 个项目循环复用，跨行业容易出现明显重复和语义不匹配。
10. 50 个商业项目虽有 10 个行业体系，但同体系 5 个项目共用同一体验渲染器；5 个布局编号主要改变首屏构图，后续区块仍高度一致。

### 2.3 P2：优化与打磨

1. 扩充 12 张循环封面图，建立与 50 个项目语义匹配的独立视觉资产。
2. 为 Buddy 浮球、Toast、Skeleton、空态和错误态统一动效、声音与减少动画策略。
3. 补齐图表坐标、单位、更新时间、数据表和导出格式。
4. 优化超宽屏留白、移动端安全区、触控热区、长标题断行和中英文排版。
5. 为草图增加高级对齐/图层，为文档增加目录/长文体验，为浏览器增加抓取内容对比。
6. 账户菜单中的积分、成长计划、主题等非核心能力在真实链路完成后再做视觉深化。

## 3. 入口与全局框架逐界面建议

| 界面 | 当前状态 | 主要问题 | 修复方案 | 优先级 |
|---|---|---|---|---|
| 登录 | 有中英文、表单校验、密码显隐 | 完全是假登录；忘记密码、条款、隐私是假入口 | 接真实会话；补错误码、锁定、忘记密码、条款链接；若为本地模式则移除伪密码 | P0 |
| 注册 | 可选姓名和四种角色 | 不创建真实账号；角色与姓名只写本地存储/全局偏好 | 原子化创建身份、工作区、角色；失败不能先显示成功；增加重复邮箱、网络失败、回滚状态 | P0 |
| Google/GitHub | 有按钮和加载态 | 仅写入 “Google/GitHub” 作为用户名 | 接 OAuth；未配置时隐藏按钮，不显示假成功 | P0 |
| 首次选角 | 四角色卡、双语、响应式 | 保存失败后仍直接跳转；没有服务端确认或失败反馈 | `PUT /api/db/role` 成功后跳转；失败时保留选择并可重试；标注每角色会获得哪些导航和项目 | P1 |
| 左侧导航 | 按角色动态生成 | 无跳到主内容链接；窄屏信息密度和当前页朗读不足 | 增加 skip link、`aria-current=page`、移动端底栏/抽屉模式、键盘完整导航 | P1 |
| 底部用户名与账户菜单 | 顶层 Popover、向上展开、主题适配 | 菜单项目真假混杂；菜单打开后缺少方向键菜单导航 | 实现 roving tabindex、上下键/Home/End；真实功能与本地体验明确分区 | P1 |
| 模型选择器 | 三个 Agnes 模型、配置检测 | 密钥缺失仍能选择；错误只在生成后出现 | 不可用模型禁用并解释原因；健康检查展示延迟、配额与最后检查时间；支持刷新 | P0 |
| Buddy 浮球 | 有气泡提示 | 只轮播文案，不是可完成任务的助手入口 | 要么接真实助手/帮助中心，要么降低为非交互装饰并从 Tab 顺序移除 | P2 |
| 全局 Toast | 已覆盖多数操作 | 成功/失败都用短暂 Toast；不可回看，屏幕阅读器信息不分级 | 成功用状态区，失败用持久 Banner/行内错误；`role=status` 与 `role=alert` 分开 | P1 |
| 右侧开发预览 | 可通过端口启动 | Sandbox ID 每轮变化，聊天中的旧 URL 必然失效 | 只依赖 Arena 当前预览卡，不输出持久旧链接；加入动态启动脚本与健康门禁 | P0 |

## 5. 工作台主视图逐项建议

| 主视图 | 当前可用能力 | 主要缺口 | 修复建议 |
|---|---|---|---|
| 首页创作器 | 类型、技能、插件、设计系统、项目引用、模型、发送 | 多个添加入口是假功能；服务健康无前置门禁 | 所有可见入口必须落到真实选择/授权/上传；发送前统一 preflight；创建失败不能进入“离线假生成” |
| 生成工作区 | 真实 API、进度、停止、版本产物、持久化事件 | 持久化失败后永久切 `offline`，不自动补传；异常中断被推导为 idle | 建立待同步队列和重试；增加 reconnect/resume；明确 running/interrupted/failed/retryable；刷新后恢复媒体任务 |
| 产物预览弹层 | 沙箱 iframe、上下滚动、复制 HTML、下载媒体、新窗口 | 无 Escape、焦点陷阱、焦点恢复；新窗口 Blob URL 未回收 | 按标准 Dialog 实现；关闭后回到触发卡；回收 Object URL；显示 sandbox 限制和加载失败 |
| 第二大脑 | 可读 `/api/memory` 索引 | 无真实条目时静默回退演示数据；解析 Markdown 索引过于脆弱 | 使用结构化 memory API；真实空态而非假数据；支持来源、删除、编辑、敏感信息控制和引用定位 |
| 模板列表 | 18 套、分类、精选、收藏、预览 | Daemon 的 `realDTpl` 已加载但完全未参与渲染 | 合并/区分内置模板和用户模板；显示来源、版本、更新时间；真实模板 API 数据必须可见 |
| 设计系统 | 可读取真实 Design System | 卡片直接用未转义服务端 HTML；“应用”只改变当前内存选择 | 安全渲染；将项目与设计系统关系持久化；提供详情、Token、组件预览、版本和编辑入口 |
| 社区 | 卡片和榜单视觉完整 | 完全静态，所有点击均为演示 Toast | 接真实公开模板/作品源；实现详情、收藏、Remix、作者与分页；若暂无后端，改成明确的“示例画廊” |
| 评审 | 部分真实 | 缺版本预览、意见、失败回滚 | 见 PM 方案 |
| 交付物 | 静态示例 | 无真实文件操作 | 见开发者方案 |
| 成员 | 静态示例 | 无真实成员操作 | 见管理员方案 |
| 审批 | 静态示例 | 无真实审批持久化 | 见管理员方案 |
| 管理统计 | 可用真实 `/api/db/stats` | 请求失败时静默显示静态数字，用户无法区分真假 | 失败显示离线/错误状态，不回退伪真实数据；图表补坐标、单位、文本摘要 |

## 10. 跨界面质量问题

### 10.1 数据真实性

- 失败时不要静默显示静态数据。每个数据区必须明确区分 `loading / live / empty / offline / error`。
- 社区、交付物、成员、审批、账户积分/套餐若暂时无真实后端，应明确标为“本地体验”或隐藏，不能模拟已经完成真实操作。
- 项目、角色、设置、账户数据必须按真实身份和工作区作用域存储，不能共享全局偏好。

### 10.2 可访问性

- 建立全局 `:focus-visible` Token，禁止只写 `outline: none` 而没有替代焦点样式。
- 所有 Dialog 实现焦点陷阱、Escape、关闭后焦点恢复和背景滚动锁定。
- 图表提供文本摘要和数据表；颜色不能是唯一状态表达。
- 图标按钮提供 `aria-label`；选择项使用 `aria-selected`/`aria-pressed`/`aria-current` 的正确语义。
- 运行 axe-core，并以 WCAG 2.2 AA 作为合并门禁。

### 10.3 响应式

- 基准宽度：360、390、768、1024、1440、1920。
- 不允许为了适配手机直接隐藏主要数据；改成堆叠、横向滚动、折叠或详情页。
- 草图、模板预览、项目预览在触屏上需要可见的缩放/返回/关闭控件。
- 安全区使用 `env(safe-area-inset-*)`，移动端按钮触控区至少 44×44。

### 10.4 性能

- 项目列表默认只加载静态封面；点击或进入视口后再创建 iframe。
- 对 56 项目进行分页/虚拟化；搜索与筛选不重建全部 iframe。
- 模板缩略图不要重复生成完整 13 页 DOM；预览打开后按需渲染当前页和邻页。
- 目标：项目页首次只创建不超过 12 个卡片 DOM、0 个运行脚本 iframe；滚动期间不出现明显长任务。

### 10.5 安全

- 所有来自 API、项目元数据和用户输入的字符串默认使用 `textContent`。
- 保留 Artifact iframe 的 opaque-origin sandbox；按功能最小化 `allow-*`。
- 诊断导出需移除密钥、Token、绝对路径和隐私内容。
- 登录/积分/奖励/审批不能以 localStorage 作为权限或余额权威来源。

### 10.6 国际化

- 将模板画布、商业项目、设计系统产物中的硬编码文案纳入 i18n。
- 中英文分别做溢出测试；英文长标题不应依赖缩小字体解决。
- 日期、金额、单位使用 `Intl`，不混用 `¥/$` 和固定中文时间。

## 11. 推荐实施顺序

### 批次 A：可靠性和真实性（P0）

1. 动态 Preview 启动脚本与健康门禁。
2. 明确“真实账号”或“本地单用户”产品模式，移除伪登录。
3. Agnes 配置预检与可操作错误页。
4. 修复角色项目过滤；为 PM/Dev/Admin 持久化 Starter。
5. 修复模板分享路由。
6. 修复服务端字符串 XSS。
7. 隐藏或接通首页全部 Demo 入口。

### 批次 B：核心工作流

1. 评审、交付物、成员、审批改为真实数据与状态机。
2. 生成事件离线补传、恢复和失败重试。
3. 项目预览/模板预览按标准 Dialog 重构。
4. 五个工作台补齐失败、冲突、恢复和可访问性。

### 批次 C：模板真实性

1. 18 套模板逐套建立 13 个独立页面组件。
2. 为每套实现至少 3 条领域级任务链。
3. “使用模板”创建真实项目和页面结构。
4. 加 234 页视觉回归、键盘与交互测试。

### 批次 D：56 个项目深化

1. 先逐个完成 6 个旧 Starter 的原生重构。
2. 再按 Commerce → SaaS → Service → Editorial → Knowledge → Mobile → Dashboard → Event → Portfolio → Industry 顺序深化。
3. 每个项目补专属数据、资产、三条任务、完整移动端和英文内容。
4. 为 56 个项目逐个运行 JSDOM/浏览器交互测试，不再只抽测第一个项目。

### 批次 E：性能与发布门禁

1. 项目缩略图静态化、分页/虚拟化。
2. axe-core、360/768/1440 视觉回归、键盘回归。
3. API 合约、离线、错误注入和恢复测试。
4. 发布前建立“所有可见按钮均有真实结果”的自动扫描和人工清单。

## 12. 建议验收标准

1. 页面上不存在“暂未接入真实功能”入口；未完成能力必须隐藏或明确为不可用。
2. 四角色只看到各自项目；刷新、重启后项目与状态仍存在。
3. 登录不再接受任意账号，或产品明确改成无登录的本地工作区。
4. Agnes 未配置时无法误进入生成；配置后文本/图片/视频各有成功与失败验证。
5. 18 套模板各 13 页通过结构差异检查；分享链接可在新会话准确恢复。
6. 56 个 Starter 每个至少 3 个按钮产生可验证的领域状态变化，并通过自动测试。
7. 项目列表首屏不加载 56 个完整 iframe；搜索/筛选无明显卡顿。
8. 360、768、1440 三档不丢失主要内容，所有页面可上下滚动。
9. 键盘可完成登录、导航、创建、项目预览、模板预览、账户菜单和五个工作台任务。
10. 所有 API 数据经过安全转义；恶意标题/作者/摘要不能执行脚本。
11. 所有真实数据区有明确 Loading、Empty、Error、Offline 和 Retry。
12. 中英文界面不出现无意的混合文案和布局溢出。

## 13. 建议先确认的产品决策

实施前建议只确认两项，不应继续让代码同时维持互相矛盾的模式：

1. **身份模式**：接真实 OpenDesign 登录，还是明确做本地单用户工作区？默认建议接真实身份；如果选择本地模式，应彻底移除密码、OAuth、套餐购买等伪在线能力。
2. **演示数据策略**：默认建议“真实数据优先，失败显示错误，不静默回退假数据”；示例内容只允许在用户主动进入“示例模式”时出现。

在这两项确定后，建议按批次 A → B → C → D → E 实施，避免先继续扩充视觉内容、后续又因身份和数据模型返工。
